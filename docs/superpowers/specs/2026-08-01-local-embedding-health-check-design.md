# 本地嵌入健康检查设计

## 目标

在“设置 → 模型配置 → 本地嵌入”中增加“测试本地模型”操作，验证当前**已保存**的
本地 GGUF、llama-cpp-python 后端和一次真实嵌入推理均可正常工作。

## 范围与非目标

- 只测试本地 embedding；不调用 LLM、远程 API、检索或知识库写入。
- 使用固定短文本生成一条向量，不持久化任何内容，也不修改当前配置。
- 测试目标是当前保存的 `embedding_local_model_file`，不是表单尚未保存的草稿。
- 仅在当前配置为本地嵌入、后端已安装且模型文件下载完成时可点击。

## API

新增受 `get_current_user` 保护的 `POST /api/v1/system/local-models/test`。

路由调用现有 `embedding_backend._local_client()` 的异步 `generate()`，以固定短文本
完成一次真实嵌入。响应如下：

```json
{
  "ok": true,
  "model_file": "bge-m3-Q8_0.gguf",
  "dimensions": 1024,
  "elapsed_ms": 42
}
```

前置条件不满足或推理失败时，响应 `{ "ok": false, "message": "…" }`；路由仍返回 200，
以便设置页把可读错误直接呈现给用户。未登录请求仍返回 401。

## 前端交互

本地模型列表下方新增“测试本地模型”按钮。按钮需要：

1. 本地推理后端状态为 `ready`；
2. 当前保存的模型文件在模型状态中为 `ready`；
3. `embedding_provider` 为 `local`；
4. 没有进行中的安装、下载或测试请求。

点击期间显示加载状态。成功后在按钮旁显示模型文件、向量维度与耗时；失败后显示后端
返回的错误。模型下拉框仍只影响草稿；用户更换模型后须先“保存并生效”再测试。

## 错误处理

- API 模式：提示先选择本地嵌入并保存。
- 未安装 llama-cpp-python：提示先下载推理后端。
- 模型未下载：提示下载当前选中的模型。
- 加载或推理异常：返回原始安全错误文本，前端通过现有错误提示呈现。

## 测试与验收

- 后端单测：未认证为 401；API 模式、缺后端、缺模型返回可读失败；模拟本地客户端时返回
  文件名、向量维度和非负耗时。
- 前端纯逻辑单测：按钮仅在所有前置条件满足时启用。
- 回归：API pytest、Web 单测/类型检查/lint/i18n、桌面类型检查和 `git diff --check`。

## 验收标准

用户在已下载后端和模型并保存为本地嵌入后，点击一次按钮即可看到成功的模型名、维度和耗时；
任一前置条件不满足时，按钮禁用或得到明确可操作的错误，不会触发外部请求或写入知识库。
