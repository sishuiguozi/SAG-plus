# 本地嵌入健康检查设计

## 目标

在“设置 → 模型配置 → 本地嵌入”中增加“测试本地模型”操作，验证当前表单中选择的
本地 GGUF、llama-cpp-python 后端和一次真实嵌入推理均可正常工作。

## 范围与非目标

- 只测试本地 embedding；不调用 LLM、远程 API、检索或知识库写入。
- 使用固定短文本生成一条向量，不持久化任何内容，也不修改当前配置。
- 测试目标是表单草稿的 `embedding_local_model_file`、上下文长度和线程数；不要求先保存。
- 仅在表单选择本地嵌入、后端已安装且草稿模型文件下载完成时可点击。

## API

新增受 `get_current_user` 保护的 `POST /api/v1/system/local-models/test`，请求体为：

```json
{
  "model_file": "bge-m3-Q8_0.gguf",
  "n_ctx": 2048,
  "n_threads": 0
}
```

路由只接受固定五个 bge-m3 文件名，并确认相应文件状态为 ready。它创建一次临时的
`LocalEmbeddingClient`，使用请求中的推理参数和固定短文本完成真实嵌入；临时客户端不进入
运行期单例，因此不会更改之后实际入库或检索使用的已保存模型。响应如下：

```json
{
  "ok": true,
  "model_file": "bge-m3-Q8_0.gguf",
  "dimensions": 1024,
  "elapsed_ms": 42
}
```

前置条件不满足或推理失败时，响应 `{ "ok": false, "message": "…" }`；路由仍返回 200，
以便设置页把可读错误直接呈现给用户。未登录请求仍返回 401。

## 前端交互

本地模型列表下方新增“测试本地模型”按钮。按钮需要：

1. 本地推理后端状态为 `ready`；
2. 当前表单选择的模型文件在模型状态中为 `ready`；
3. 表单的 `embedding_provider` 为 `local`；
4. 没有进行中的安装、下载或测试请求。

点击期间显示加载状态。成功后在按钮旁显示模型文件、向量维度与耗时；失败后显示后端
返回的错误。模型下拉框和推理参数直接作为测试请求发送；用户可在测试通过后再决定是否保存。

## 错误处理

- API 模式：前端禁用按钮；服务端仍校验模型文件和后端状态，避免绕过页面调用。
- 未安装 llama-cpp-python：提示先下载推理后端。
- 模型未下载：提示下载当前选中的模型。
- 加载或推理异常：返回原始安全错误文本，前端通过现有错误提示呈现。

## 测试与验收

- 后端单测：未认证为 401；拒绝未知模型、缺后端、缺模型返回可读失败；模拟临时客户端时返回
  请求模型文件、向量维度和非负耗时。
- 前端纯逻辑单测：按钮仅在草稿为本地、草稿模型就绪且所有前置条件满足时启用。
- 回归：API pytest、Web 单测/类型检查/lint/i18n、桌面类型检查和 `git diff --check`。

## 验收标准

用户在已下载后端和模型后，无需保存即可测试当前草稿并看到模型名、维度和耗时；任一前置条件
不满足时，按钮禁用或得到明确可操作的错误，不会触发外部请求、写入知识库或修改已保存配置。
