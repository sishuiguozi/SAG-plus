# SAG-plus 自动依赖与本地模型管理设计

## 目标

让 `apps/desktop` 中的 `npm run dev` 在缺少运行依赖时自动准备 Desktop、Web 和 API 环境；让用户在设置页按需安装 `llama-cpp-python` 推理后端，并选择下载一个或多个 bge-m3 GGUF 量化模型。

## 边界

- 自动准备的是代码运行依赖，不下载模型权重。
- 本地推理后端仅指 `llama-cpp-python` 的 CPU 预编译包。
- 不新增本地聊天大语言模型，也不改变远程 API 向量模式。
- 下载操作必须由已登录设置页用户主动点击触发。

## 启动依赖准备

在桌面 `dev` 前增加一个无第三方依赖的 Node 启动脚本：

1. 缺少 Desktop 依赖时，在 `apps/desktop` 运行 `npm ci`。
2. 缺少 Web 依赖时，在 `apps/web` 运行 `npm ci`。
3. 缺少 API `.venv` 时，用 Python 3.11+ 创建虚拟环境；缺少 API 包时，运行 `.venv` 的 Python 安装 `.[dev]`。
4. 任何子命令失败都保留输出并停止启动，不启动半成品服务。
5. 已满足的依赖不重新安装。

## 本地模型目录与目录清单

模型仍保存在 `settings.embedding_local_model_path()` 所在的 `models/bge-m3/` 目录。
设置页提供下列可多选的固定来源，均来自 Hugging Face 的
`gpustack/bge-m3-GGUF`：

| 文件 | 用途 |
| --- | --- |
| `bge-m3-Q4_K_M.gguf` | 最低的推荐内存占用 |
| `bge-m3-Q5_K_M.gguf` | 内存与精度平衡 |
| `bge-m3-Q6_K.gguf` | 更高精度 |
| `bge-m3-Q8_0.gguf` | 默认推荐 |
| `bge-m3-FP16.gguf` | 高内存的原始精度版本 |

模型文件名下拉框只能选择这份目录中已完成下载的文件；已存在的旧文件仍会正常显示和使用。

## 下载与安装 API

新增受当前用户认证保护的本地模型管理 API：

- 获取后端、模型目录、每个目录项的已安装/下载中/完成/失败状态。
- 安装 `llama-cpp-python`：只调用当前 API 虚拟环境的 Python，使用 CPU wheel 索引与二进制包限制。
- 批量下载选中的模型：每个文件写入同目录 `.part` 临时文件，完成时校验 HTTP 内容长度与 ETag SHA-256，再原子替换为最终 GGUF 文件。
- 后台任务在进程内运行；状态 API 提供已下载字节、总字节、进度、错误信息和完成文件。
- 同一文件的重复请求复用进行中的任务；已有且校验通过的文件不重复下载。

## 设置页

在“设置 → 模型配置 → 本地向量模型”中增加：

1. `llama-cpp-python` 状态与“安装推理后端”按钮。
2. 五个模型目录项的多选框、批量下载按钮和每项下载进度。
3. 下载完成后刷新本地模型状态与可选模型文件列表。
4. 当前本地模型选择器只列出已完成模型；保存模型选择仍沿用现有配置接口。

## 验收标准

- 删除任一依赖目录后运行 `npm run dev` 会先恢复对应依赖，再继续桌面启动。
- 未点击设置页按钮时，不下载 `llama-cpp-python` 或 GGUF 权重。
- 可同时选择五个目录项中的任意多个，下载结果独立展示。
- 失败或中断不产生可被加载的半成品 GGUF 文件。
- 已安装后端与已下载模型能被现有 `local_embedding_status` 报告为就绪。
