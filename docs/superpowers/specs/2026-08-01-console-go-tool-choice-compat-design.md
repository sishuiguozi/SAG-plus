# Console Go 工具选择兼容设计

日期：2026-08-01
状态：待实现

## 背景与结论

SAG-plus 当前会根据用户意图选择 `none`、`auto`、`required` 或指定函数形式的 `tool_choice`。实测 Console Go（`https://opencode.ai/zen/go/v1`）在启用思考时可以处理 `none` 和 `auto`，但指定 `search_context`、`get_time` 等函数或使用 `required` 会返回上游请求失败。

同一接口在仅对该次模型调用关闭思考后，可以正常接受指定工具，流式调用也能返回正确的工具调用。因此默认兼容方案为：保留 SAG-plus 的工具路由能力，只在 Console Go 的强制工具选择轮临时关闭思考；工具执行后的回答轮恢复原有思考设置。

## 目标

- 让 Console Go 稳定执行 `search_context`、`get_time` 等指定工具。
- 普通回答继续保留思考能力。
- 不改变其他 OpenAI 兼容接口的默认工具选择行为。
- 在模型配置中提供清晰、可回退的工具调用策略。
- 同时支持流式与非流式模型调用。

## 非目标

- 不修改入库抽取和 LLM 重排已有的关闭思考逻辑。
- 不通过失败后自动重试另一种工具策略掩盖错误。
- 不把所有 DeepSeek 模型或所有 OpenAI 兼容接口都判定为 Console Go。
- 不改变工具定义、工具执行器或知识库检索逻辑。

## 配置设计

新增系统配置 `llm_tool_choice_strategy`，默认值为 `compatible`，支持三档：

| 值 | 设置页名称 | 行为 |
| --- | --- | --- |
| `compatible` | 智能兼容（推荐） | 保留路由器选择；仅 Console Go 的指定工具或 `required` 调用临时关闭思考 |
| `strict` | 强制工具选择 | 完全保留路由器输出，不附加工具兼容处理；用于确认支持强制工具选择的接口 |
| `auto` | 自动工具选择 | 将指定工具和 `required` 改为 `auto`，由模型自行决定是否调用工具 |

`none` 和原本的 `auto` 在三种策略下都保持不变。已有的入库抽取、实体事件抽取与 LLM 重排作用域仍可独立关闭思考，并且优先继续生效。

设置页放在模型配置区域，字段名为“工具调用策略”，展示三档说明和推荐标记。选择“强制工具选择”且当前接口识别为 Console Go 时，应提示该组合可能被上游拒绝，但允许用户保存。

## Console Go 识别

只根据规范化后的模型基础 URL 识别：

- 主机名必须为 `opencode.ai`；
- 路径包含 `/zen/go`；
- 忽略大小写、末尾斜杠和 `/v1` 差异。

不根据模型名包含 `deepseek` 等宽泛条件判断，以免影响其他供应商。

## 请求处理流程

1. Agent 路由器按现有规则产生初始 `tool_choice`。
2. LLM 客户端构造请求参数。
3. LiteLLM 策略层读取 `llm_tool_choice_strategy`、基础 URL 和实际 `tool_choice`。
4. 按策略处理：
   - `compatible`：若为 Console Go，且选择是指定函数或 `required`，保留该选择，并只对当前请求注入关闭思考参数；否则不变。
   - `strict`：不增加工具兼容处理。
   - `auto`：将指定函数或 `required` 改写为 `auto`。
5. 工具执行完成后，下一轮通常使用 `auto`，因此不会触发 Console Go 的临时关闭思考，模型恢复正常回答行为。

Console Go 临时关闭思考复用现有供应商兼容参数：

- `reasoning_effort="none"`；
- `extra_body.thinking={"type":"disabled"}`。

处理必须是单次请求级的，不得修改全局配置或泄漏到后续调用。若当前已经处于入库抽取或重排的关闭思考作用域，则沿用既有处理结果，不重复覆盖其他请求参数。

## 后端改动范围

- 核心配置：新增枚举字段与默认值。
- 系统设置 schema：校验并向前端输出新字段。
- 设置服务：读写、推荐值和重置默认值。
- LiteLLM 请求策略：识别强制选择、Console Go URL 和三档行为。
- 不在 Agent 路由器中硬编码供应商判断，保持意图路由与接口兼容职责分离。

## 前端改动范围

- 模型配置类型增加工具调用策略。
- 模型配置表单增加三档选择及说明。
- 中英文文案同步补齐。
- 未保存配置仍遵循现有设置页保存机制，不改变其他模型配置交互。

## 测试设计

后端单元测试至少覆盖：

- 默认策略为 `compatible`。
- Console Go + 指定函数：保留函数名并关闭当前调用的思考。
- Console Go + `required`：保留 `required` 并关闭当前调用的思考。
- Console Go + `auto` 或 `none`：不因工具兼容策略关闭思考。
- `strict`：指定函数保持不变，不附加工具兼容参数。
- `auto`：指定函数和 `required` 改写为 `auto`。
- 非 Console Go：`compatible` 不改变强制工具选择和思考参数。
- 入库抽取和重排已有关闭思考作用域继续生效。
- 流式与非流式请求使用相同策略。
- 系统设置 API 能保存、读取和重置新字段。

前端验证至少覆盖：

- TypeScript 类型检查。
- ESLint。
- 中英文 i18n 键完整性检查。
- 表单能够显示并提交三档值。

## 验收标准

- Console Go 在知识库模式下可成功执行指定 `search_context`。
- Console Go 可成功执行指定 `get_time`。
- 指定工具轮的思考被关闭，工具后的回答轮恢复思考。
- “你好”等无需工具的直接回答行为不变。
- 其他接口默认继续使用 SAG-plus 原有的强制工具选择。
- 三档策略可在模型配置中保存并在重启后生效。
- 相关后端测试、前端类型检查、ESLint 与 i18n 检查全部通过。

## 风险与回退

- 上游可能改变对工具选择或关闭思考参数的支持；用户可切换为“自动工具选择”。
- 若接口被代理到不同实现但仍使用相同 URL，兼容规则仍会生效；“强制工具选择”可关闭这项特殊处理。
- 新配置默认使用 `compatible`，旧安装无需迁移即可获得修复；回退代码后，数据库中的额外配置键应被旧版本安全忽略。
